### Padding under lockstep data parallelism

`TestDPLockstep_KernelPaddingReachesTheCluster` prices the dp2 minimax fixture's long request
padded and unpadded. The regenerated fixture states no `cudagraph_mode`, so the kernel resolves
decode steps to FULL graphs and the test's batch is not padded: 1,392,365 us padded and unpadded.
With `cudagraph_mode: PIECEWISE`, which the old fixture stated, padding adds 1,868 us (0.13%) to
that request's end-to-end time: 1,476,577 us padded, 1,474,709 us unpadded. The test now states
PIECEWISE in the scenario variant it writes, because padding exists only under that mode.

### Fixtures whose engine settings are refused

38 of the 679 generated fixtures state no `block_size`, and blis-vllm refuses to resolve one for

minimax-m3 (6), glm-5 (5), deepseek-v4-pro (4), deepseek-v3 on H200 (2). The kernel prices them,
and the tables above include them; `blis run` on one is refused until the engine resolves the
size. No test in this repository opens one.
