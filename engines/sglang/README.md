# SGLang engine

A Go model of the [SGLang](https://github.com/sgl-project/sglang) inference engine's scheduling,
KV-cache, hierarchical-cache, disaggregation and metrics behaviour, for the BLIS simulator. It
lives in the `engines/sglang` directory of the one `github.com/inference-sim/inference-sim`
module and implements the engine-neutral contract in `substrate/contracts/` (`engine.Engine`);
the simulator builds it at one site, `cmd/sglang_engine.go`. One build models one SGLang
release, named in `provenance.go` (now 0.5.23, which `stack.json` also pins); its decisions are
checked against that release's own Python classes, run on CPU with only the GPU, the clock,
transports and the platform replaced (`oracle/`).

This file is the only document of the engine's parity (X29). It states what the engine models,
proves inert, refuses and does not model. A count or status is read from a generated or checked
file, and the command that prints it follows each section, so no number is copied here.

## The pin

This build models SGLang v0.5.23, commit `297e54fd105e974cdf401e5b4d20253a22c16f90`: `Upstream` in
`provenance.go`, the `sglang` entry of `engines` in `stack.json`, and the `upstream` member of
`surface.json` name it. The SGLang source is cited as `path:lines@297e54fd`.

What a user can pin: the commit above is what this build models. A pin by tag needs the M3.2
release tag of the inference-sim module, which a maintainer cuts; this file names none, and
the module has one version for everything in it, so the engine has no tag of its own.

## Modelled

A status is `modelled` only with the traces that show it. Read the lists, not this section, for
the current set:

```sh
jq -r '.items[] | select(.status=="modelled") | .id' surface.json
jq -r '.fields[] | select(.status=="modelled") | .name' fields.json
```

In outline: the scheduler's waiting-queue policies and its settings (`max_prefill_tokens`,
`chunked_prefill_size`, `max_running_requests`, `allow_auto_truncate`, retraction by length and by
priority, priority scheduling), the paged and token allocators, the MHA, MLA and DSA KV pools, the
request pool, and the memory settings that size them (`mem_fraction_static`, `kv_cache_dtype`,
`context_length`). A field is modelled at the values its entry allows: `pp_size` only at 1, and
`dp_size` without attention data parallelism.

## Proven inert

A field is `proven_inert` when `oracle/inertness/<field>.json` records SGLang's own scheduler run
at the default and at each probe value with one result, with every read of the field and every
line using what a read stored executed; `inertness_test.go` holds the list to the files. Today
that is `stream_interval`. `inert_unproven` is a reviewed reading with no proof file; its
`evidence.note` gives the reading and the test (`lower/inert_fields_test.go`) that shows resolution
and the lowered plan unchanged. Only a `proven_inert` field is a claim of this README.

```sh
jq -r '.fields[] | select(.status=="proven_inert" or .status=="inert_unproven") | [.status,.name] | @tsv' fields.json
```

## Refused

A refused item is not approximated: the engine refuses it at start-up by its SGLang name, and the
list entry cites the open issue that models it. `TestEverySettingSelectedSurfaceItemIsRefusedAtStartUp`
holds this for each surface item one setting selects (a class SGLang picks from the model, a
metric family or a loop is refused where its configuration is).

SGLang's own refusals are raised with SGLang's message, quoted from the source at the pin in
`oracle/refusal_quotes.json`: an unknown `schedule_policy`, `shortest-prefill-first` without a
prefix cache, `tlru` off the unified tree, priority scheduling over `lpm`, and priority retraction
without priority scheduling. `out_of_scope` has one reason, `hardware` (Ascend NPU and Apple MLX
classes, since every target chip is CUDA).

```sh
jq -c .counts surface.json
jq -r '.items[] | select(.status=="refused") | .issue' surface.json | sort | uniq -c
jq -r '.items[] | [.category,.status] | @tsv' surface.json | sort | uniq -c
```

## Not modelled, and not yet proven

- **Every other field.** A `not_modelled` field set away from its default is refused by its upstream
  name, and a name SGLang does not declare is refused too
  (`jq -r '.fields[].status' fields.json | sort | uniq -c`).
- **Coupled replay (FID-9) is not yet proven.** The goal is that the engine inside the simulator
  reproduces the oracle's per-request completion order, per-tier KV hits and transfer events on the
  scheduler scenarios. No test does that. The nearest is `TestEnginePassesEqualSGLangs` in
  `core/sglang/engine_test.go`: it drives the engine through the contract, with a flat price and
  outside the simulator, over the scheduler goldens in `core/sched/testdata/golden-sched/`, and
  compares each pass's requests, their order and their token counts in the normal and the overlap
  loop. It skips scenarios that state the `random` policy, priority scheduling, a queue limit,
  `prefill_max_requests`, a routing key, disabled consecutive-prefill overlap, or a sampled token
  other than 13. It compares no completion order, no per-tier KV hit and no transfer event (HiCache
  and P/D are refused, so none exists). `TestSGLangRunAndReplayAreOneResult` in
  `cmd/sglang_engine_test.go` holds a run and the replay of its trace to one result (INV-13); it
  is no comparison with the oracle.
- **Speculation has no scheduler oracle trace.** Resolution of the EAGLE-family settings at top-k 1
  is checked against SGLang's own resolution, and the engine builds a draft chain from it
  (`TestTheFactoryBuildsAnEagleChain`), but no golden records a speculative pass. The lists carry
  these items as refused or `not_modelled` under #2355, and the lists are what this engine claims.
- **HiCache and metrics are ported, not run by the engine.** `core/hicache` and `core/metrics` are
  compared with their goldens; the engine refuses `enable_hierarchical_cache`.
- **The lists can lag the code.** The scheduler loops and the radix cache run in the engine and
  the scheduler goldens cover them, yet `surface.json` lists them as refused until their entries
  in `engines/sglang/tools/surface/status.json` gain trace evidence.
- **Durations.** The oracle replaces the GPU, so it checks scheduling decisions, memory sizing and
  lowering, not how long a pass takes. Step time is the cost model's (`substrate/kernel`), priced
  on the shape the engine emits; its accuracy is that model's to show.
- **No command prints the surface list.** `blis fields` prints the field list of the engine a
  scenario names; read the surface list from `surface.json`.

## Layout

| Path | What |
|---|---|
| `core/sched`, `core/cache`, `core/hicache`, `core/metrics`, `core/sglang` | the scheduler, the radix and pool caches, the hierarchical cache, the metrics, and the engine that ties them together |
| `config/` | `ServerArgs` resolution and validation |
| `rules/` | SGLang v0.5.23's engine rules: the answers a cost model and a validator ask of the engine release |
| `lower/` | lowering a model to kernel implementations |
| `sglangengine/` | how a simulator gets the engine: the factory registration |
| `fields.json`, `fields/` | the field list, its generator and hand-written statuses (`fields/README.md`) |
| `surface.json`, `engines/sglang/tools/surface/` | every feature the release can select, with its status; generated, never edited |
| `oracle/` | the Python side: SGLang's classes with the GPU mocked, goldens and runners (`oracle/README.md`) |

## Build, test and run

Run from `engines/sglang/`:

```sh
go build ./... && go vet ./...
go test ./...
golangci-lint run ./...         # v2.14.0
```

The oracle checks run as the jobs of `.github/workflows/oracle-sglang.yml`, which
`.github/workflows/ci.yml` calls when a change touches `engines/sglang` or `substrate`; the header
of `scripts/ci-changes.sh` says how a change selects jobs. `AGENTS.md` gives the rules for a change.
