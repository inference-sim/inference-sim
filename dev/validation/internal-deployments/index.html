    Internal llm-d deployments (DSV4.1 H200)¶

    BLIS binaries these results describe

    • (devel)+9e3c509c8788fe0743605a8f06e0bf5c1c39ac1f, binary sha256 29fb09054a10ee51dc104f491cb09337e0ba527055b85653d281f23230451dff

    DeepSeek-V4.1-Flash on H200 under vLLM, measured on internal llm-d deployments: single-replica ablations of the TP8 deployment (no DSpark, no KV offload, no Engram), a TP4 deployment, and one- and two-replica aggregated deployments behind the EPP router. The workload is an agentic multi-turn corpus replayed closed loop, 900 s per level, c8 to c512.

    These runs are not public, so the pages cite no URL and carry no measured value; the source reports are pinned by sha256 in the validation inputs.

    Build: 9e3c509c. Signed error 100 * (BLIS / measured - 1).

    unremovable KV CPU tier: vLLM's blocks_per_chunk 4 is not representable (BLIS uses 1), and BLIS does not price the CPU-to-GPU reload. Material only where measured CPU-tier hits are above zero.

    Gap re-checks¶

    Each modelling gap claimed for these deployments, re-checked by paired BLIS probes (latest build):

    gap empirical verdict
    CPU offload tier: CPU-to-GPU reload unpriced CONFIRMED
    Engram host gather CONFIRMED (partial): placement changes KV only; step-time effect <= 2.1% ITL at c32
    all-to-all backend moot at DP=1 (byte-identical across 4 backends); REFUTED at DP=2: deepep_low_latency vs deepep_high_throughput differ
    inter-node fabric immaterial

    What would make an arm EXACT: the raw run artifacts and ablation manifest kept with the run; every UNSTATED setting stated; BLIS representing vLLM's blocks_per_chunk and pricing the CPU-to-GPU reload (or a run without CPU-tier hits); and the speculative acceptance schedule replayed per position.
